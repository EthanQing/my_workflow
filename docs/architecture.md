# Architecture

Task baseline: AEGIS-001 / P1, desktop DSH 0.2.1-rc.2. This document describes implemented configuration, not a separate orchestration engine.

`package.json` declares an ordered `dsh.bundle.patch` list. Each YAML file inserts one `@deepseek-ai/dsh-agent-preset` declaration. Lead mounts six individually named `@deepseek-ai/dsh-tool-subagent` consumers, each selecting `provider: spawn`, a distinct `agentPreset`, and `maxDepth: 1`. Children contain no delegation tools. Host services remain owned by DSH; the bundle neither replaces the registry nor changes its default preset.

The local in-process spawn provider's `prepareContinuable` capability selects the official managed local lifecycle. Each child owns a session ID and its own prompt/tool composition. Completion releases its active instance. Official parent catalog projections and JSONL session persistence provide identity and restoration. `list_agents` reports running/inactive children; `send_message` accepts either state. Persistent history and a permanently running process are different things.

Lead keeps the complete task envelope in conversation: task ID, plan version, workspace, initial commit/status or non-Git baseline, existing edits, original request/clarifications, approval evidence/scope, full Planner plan, current code state, checks and cumulative rework. This is coordination context, not a custom persisted database. Role reuse preserves useful investigation, never authorization across tasks.

Recovery first consults the existing catalog and workspace-authorized raw session reads. Desktop defaults to `openAt: never`, so full-text search is optional, never a recovery prerequisite. On disabled search, read the original child with `session_event_read`, `seq: 0, after: 50`; advance from the last returned sequence, inspect subsequent windows, and fully read the identified result event. No index is enabled and no replacement child is spawned. Completed, still-valid work is reused. Missing original evidence is reported before repeat execution; file changes or Git commits are inspected before retries. Cold restoration needs official session storage and currently registered matching preset IDs. Same-workspace history tools require exact cwd equality. Restoring under a new bundle version loads its current preset definition.

Read-only role tool sets omit shell/write/edit. Coder has file writes and shell; Curator has file writes without shell. Curator's documentation-only scope, Coder's no-knowledge/no-Git rules, Lead's investigation-only shell use, writer serialization, approval gates and three-round maximum are prompt instructions. They are not strict security enforcement. No custom command interceptor is included. An untrusted/misbehaving model requires host sandbox and permissions for stronger guarantees.

`tests/` and `scripts/test-runtime.mjs` are development-only and excluded from the published package whitelist. They exercise the installed desktop's actual Loader, preset registry, Agent loop, model-visible tools, subagent manager, spawn provider, persistence and SQLite history query with a deterministic model adapter. No product runtime JavaScript is shipped.
